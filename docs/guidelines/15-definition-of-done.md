# Definition Of Done

## Purpose

This document defines when work is considered complete.

A task is not complete when it works.

A task is complete when it satisfies all quality requirements.

---

# Core Principle

Working code ≠ Done

Done means:

Working

*

Tested

*

Documented

*

Reviewed

*

Maintainable

---

# Global Definition Of Done

Every task must satisfy:

✓ Feature implemented

✓ Types added

✓ Tests added

✓ Documentation updated

✓ Accessibility verified

✓ Performance reviewed

✓ Standards followed

✓ Code reviewed

---

# Component Definition Of Done

A component is complete when:

✓ Typed

✓ Accessible

✓ Responsive

✓ Reusable

✓ No business logic

✓ Tested

✓ Follows naming standards

✓ Uses design tokens

✓ Uses approved architecture

---

# Feature Definition Of Done

A feature is complete when:

✓ Requirements implemented

✓ Edge cases handled

✓ Loading states implemented

✓ Error states implemented

✓ Tests added

✓ Documentation updated

✓ Performance reviewed

✓ Accessibility verified

---

# API Definition Of Done

An API integration is complete when:

✓ Service created

✓ Types created

✓ Errors handled

✓ Loading states handled

✓ Query keys centralized

✓ Tests written

✓ No direct API calls in UI

---

# Store Definition Of Done

✓ State minimal

✓ Selectors created

✓ Tests written

✓ Persistence reviewed

✓ No duplicated state

✓ Keyboard navigation

✓ Focus states

✓ Labels

✓ Semantic structure

---

# Documentation Definition Of Done

Every significant feature requires:

Purpose

Responsibilities

Dependencies

Usage examples

Future considerations

---

# Testing Definition Of Done

Required:

✓ Unit tests

✓ Integration tests

✓ Failure path coverage

✓ Edge case coverage

Critical features require:

✓ E2E tests

---

# Performance Definition Of Done

Feature must not:

Introduce obvious rerenders

Increase bundle size unnecessarily

Cause frame drops

Reduce responsiveness

---

# Pull Request Definition Of Done

Before merge:

✓ CI passes

✓ Lint passes

✓ Type check passes

✓ Tests pass

✓ Review completed

✓ Documentation updated

---

# Release Definition Of Done

Release is complete when:

✓ Features verified

✓ Performance verified

✓ Accessibility verified

✓ Documentation complete

✓ No critical bugs

✓ Monitoring enabled

---

# Final Rule

The question is never:

"Does it work?"

The question is:

"Would we be comfortable maintaining this implementation for the next three years?"

If the answer is no:

The work is not done.
